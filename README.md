# zimbra-ir-triage

Триаж инцидента на почтовом сервере Zimbra: один проход, который отвечает на вопрос
«скомпрометирован ли сервер и как именно» — без изменения состояния системы.

Написан по следам разбора ситуации, когда почтовый сервер попал в спам-блок-листы и нужно было
быстро понять, рассылает ли он спам сам, через чей ящик, и не остался ли у атакующего доступ.
Собирать это руками — несколько часов; скрипт делает за один прогон.

## Что важно знать до запуска

**Только чтение.** Ничего не меняет: не правит конфигурацию, не сбрасывает пароли, не удаляет
письма, не перезапускает службы.

**Не мешает работе.** Понижает себе приоритет CPU и ввода-вывода (`renice`, `ionice`), поэтому
запускается на боевом сервере без простоя почты.

**Не распаковывает архивы логов на диск.** Ротированные `.gz` за последние 30 дней читаются
потоком.

**Работает через `ldapsearch`, а не через тяжёлые JVM-утилиты** — на больших каталогах разница
в минутах.

Вывод идёт в терминал с подсветкой и параллельно в текстовый отчёт.

## Модули

**1. Среда и репутация.** Параметры хоста, состояние служб Zimbra, перечень пакетов. Проверка
IP по восьми спам-блок-листам (Spamhaus ZEN, Barracuda, SpamCop, SORBS, Mailspike, Manitu,
UCEPROTECT) с жёстким таймаутом.

**2. Очередь Postfix.** Размер очереди, разбивка активной и отложенной через `qshape`,
топ отправителей и доменов-получателей. Аномальный объём подсвечивается.

**3. Логи Postfix и SASL — поиск скомпрометированных ящиков.** Учётные записи с ненормальным
объёмом исходящей аутентифицированной почты, сопоставление ящиков с IP-адресами клиентов,
суточный график отправленного за 30 дней (видно, когда началась рассылка), топ источников
неудачных аутентификаций.

**4. Конфигурация, пересылка и правила Sieve.** Проверка на открытый релей
(`zimbraMtaMyNetworks`), глобальный перехват почты (`always_bcc`, `sender_bcc_maps`,
`recipient_bcc_maps`), список администраторов домена и глобальных, поиск несанкционированной
автопересылки (`zimbraPrefMailForwardingAddress`) и бэкдорных правил Sieve — тех, что гасят
уведомления о недоставке или перенаправляют письма.

**4.1. Настройки безопасности.** Доступность админ-консоли (порт 7071) на внешнем интерфейсе,
защита от подмены внутреннего отправителя, политика блокировки учётных записей, состояние
ограничителя исходящей почты, наличие SPF, DMARC и DKIM.

**5. Веб-логи и журнал аудита.** Поиск следов эксплуатации известных RCE в Zimbra
(CVE-2019-9670, CVE-2022-27925, CVE-2022-37042, CVE-2022-41352, CVE-2024-45519 и характерных
путей вида `mboximport`, `/service/admin/soap`, `zmFilterClient.jsp`, `upload?fmt=raw`).
В `audit.log` — несанкционированные сбросы паролей (`SetPasswordRequest`), выгрузка глобальной
адресной книги (`SearchGalRequest`), всплески аутентификаций.

**6. Персистентность.** Процессы, запущенные из удалённых исполняемых файлов
(`/proc/*/exe (deleted)`). Поиск веб-шеллов: файлы `.jsp`, `.jspx`, `.sh`, `.py`, `.php`, `.war`,
созданные или изменённые за последние 60 дней в каталогах Jetty и `/tmp`, с проверкой на
сигнатуры (`Runtime.getRuntime`, `ProcessBuilder`, `eval`). Задания cron для `root` и `zimbra`,
`authorized_keys`, изменённые юниты и таймеры systemd, интерактивные оболочки и сетевые утилиты
под пользователем `zimbra`.

**7. Сводка.** Матрица из десяти пунктов и список действий для реагирования.

## Запуск

```bash
git clone https://github.com/Asw3x/zimbra-ir-triage.git
cd zimbra-ir-triage
chmod +x zimbra_ir_triage.sh
sudo ./zimbra_ir_triage.sh
```

Требуется root: часть проверок читает системные каталоги и кусты, к утилитам Zimbra скрипт
понижает права до пользователя `zimbra` сам.

Проверено на RHEL / CentOS / Rocky / AlmaLinux / Debian / Ubuntu, Zimbra 8.x, 9.x, 10.x.

## Чего инструмент не делает

- Не чинит и не изолирует: только собирает факты и показывает, куда смотреть.
- Не заменяет полноценную форензику — образ диска и память он не снимает.
- Не доказывает отсутствие компрометации. Чистый отчёт означает, что проверенные места чисты.
- Сигнатурный поиск веб-шеллов ловит типовое, а не целевое: обфусцированный или нестандартный
  шелл может не сработать по сигнатурам, и каталоги всё равно стоит просмотреть глазами.
